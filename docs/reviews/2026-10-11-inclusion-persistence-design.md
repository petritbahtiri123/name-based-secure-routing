# Proposed decision INCLUSION-PERSISTENCE-01

Status: proposal for approval; design only. No implementation, ACL changes or
persistence tests authorized by this document. Scope is the existing explicitly
selected inclusion-v2 local conformance path, one log/scope/target lineage and
one cooperating writer. Runtime/live flags remain false. No service, trusted
bootstrap, new keys, wire allocation or production provisioning is introduced.

## Choice and reuse

Recommend a separate versioned snapshot and repository. Reuse the canonical
ASCII JSON conventions and bounded descriptor-bound read algorithm from
`nbsr/federation/store.py`, `secure_write_private` unchanged, and the exclusive
create lock pattern from `nbsr/continuity.py`. Do not change federation schema 1
or reinterpret its replay digests. Sharing small internal helpers can be
considered only when implementation review demonstrates identical semantics.

Alternatives: overloading schema 1 loses the defined record/event binding and
silently changes its contract; a database or new external trust service adds
unapproved infrastructure and still needs a provenance policy. Neither is
recommended. A single snapshot is simpler but offers no retained second copy
for an interrupted replacement. Two complete snapshots permit conservative
process-interruption recovery without splitting security facts across files.

## Exact persisted contract

Proposed format identifier `nbsr-inclusion-local-snapshot-v1`, schema integer 1.
Closed root fields: `format`, `schema`, `profile`, `amendment_sha256`,
`context_binding`, `transaction`, `previous_snapshot_digest`, `state`,
`snapshot_digest`. Profile is the existing exact inclusion profile. Amendment
digest binds the exact selected registry bytes and its inherited parent pins.
Transaction is a positive integer, starts at one, advances by exactly one for
every changed state, including a new event binding on an idempotent record.
It is local ordering metadata, not authority or a clock.

`context_binding` is a lowercase SHA-256 hex digest supplied independently by
the local test caller for its explicit accepted configuration fixture. It is
compared to the caller's expected value; the loader cannot derive acceptance
from a matching stored value. No universal authority-configuration encoding is
allocated here. Cross-context migration is rejected by this version.

`state` has exactly: `log_id`, `scope_cbor`, `target_cbor`, `floor`, `record`,
`retained_revocations`, `requests`. Binary values use lowercase even-length hex;
digests are exactly 32 bytes. Log identity follows the existing checkpoint
validator. Scope and target retain exact deterministic CBOR from the accepted
record; re-encoding must reproduce those bytes. `floor` is the exact accepted
checkpoint digest. `record` is the complete original canonical v2 R, bounded by
the existing 32768-byte record parser, with no omitted fields or reconstruction.
Generation, sequence, previous digest, terminal status and typed enforcement
are derived from R, never separately editable metadata. This version persists
only post-accept states, so R is never null. The first state is generated by an
explicit fixture initialization transaction after successful verification.

`retained_revocations` is a sorted unique array of record digests containing R's
digest and preserving every previously retained digest. `requests` is a sorted
unique-by-event array of `[event_id, record_digest]` pairs. Event encoding and
length follow the existing Option-C validator. Each bound digest must be retained.
No timestamps, replay eviction or garbage collection are introduced. Terminal
R cannot acquire a successor; older revocation markers are never removed.

Canonical encoding reuses sorted keys, compact separators, ASCII JSON and one
terminal newline. Reject duplicate/unknown fields, booleans as integers,
noncanonical hex/CBOR, invalid types, and any byte representation that fails
exact canonical re-encoding. `snapshot_digest` is SHA-256 of the canonical root
with only that field omitted (without the terminal newline). The format and
profile thus participate in the integrity binding. `previous_snapshot_digest`
is null only at transaction one; otherwise it is the exact preceding digest.
Hashes detect alteration; they are neither signatures nor freshness evidence.

Reuse the existing 262144-byte encoded snapshot ceiling and 4096-record ceiling
as local storage resource limits: the latter caps the aggregate count of one R,
retained digests and event bindings. Encoded size may bind first. These are not
new protocol capacities. Exhaustion rejects the transaction before any write;
it never evicts safety state. No new time-based retention period is invented.
The existing 86400-second replay minimum is not permission to delete bindings.

## Transaction, writes and recovery

Files within one private test-owned directory: `inclusion.json` (primary),
`.inclusion.json.watermark` (complete second snapshot), and
`.inclusion.json.lock` (exclusive-create cooperating-writer lock). Temporary
names are those generated by the existing private writer in that same directory.
The second snapshot is a recovery copy, not an independently trusted watermark.

Hold a repository-instance mutex and the exclusive file lock across reads,
verification of the expected prior snapshot digest, candidate validation, both
writes and result publication. Acquire the file lock with exclusive create;
never infer that a lock is stale from its age/PID. All cooperating reads that
may restore state or repair the primary use this ownership protocol. A stale
lock fails closed until separately authorized, verified owner cleanup.

1. Read and validate both files using bounded descriptor-bound regular-file
   reads. The existing readers reject final symlinks/nonregular files and
   compare descriptor identity; they do not supply complete Windows ancestor
   reparse or alias validation. This proposed repository accepts only a fresh,
   prevalidated canonical test root and the fixed child names above. Explicit
   root/ancestor reparse and alias checks are additional proposed work, required
   before writes, not an inherited reader guarantee. Inspection is not a
   hostile-filesystem sandbox and assumes no concurrent hostile path mutation.
2. Verify the candidate against the currently loaded state and caller-supplied
   context. Preserve all bindings and retained facts, exact scope/target/log,
   ordinary same-generation lineage, and the existing F=A or exact F=C rule.
   Persist only a successful changed result. Rejection/pending writes nothing.
3. Write the complete candidate to the watermark FIRST, then the primary, using
   `secure_write_private` for each. Each call writes a same-directory temporary
   file, flushes and fsyncs its contents, replaces the destination, and applies
   final private permissions. This ordering is intentionally separate from the
   existing federation repository's primary-first algorithm.
4. Return the changed local result only after both calls succeed. A failure
   after either replacement is an uncertain commit: return storage failure,
   latch the instance unavailable, release only this attempt's lock normally,
   and require reload. Never return an ordinary verifier rejection for a
   possibly committed state. No external enforcement side effects are included.

Recovery table, after ownership and structural checks:

| Primary | Watermark | Local process-interruption outcome |
|---|---|---|
| Same complete snapshot | Same | Candidate for caller-authorized restore |
| Valid predecessor | Valid immediate successor linking its digest and preserving all safety facts | Candidate is watermark; repair primary before success |
| Missing | Valid | Candidate is watermark; explicit recovery and caller's exact expected digest required, then repair |
| Missing | Missing | Fail closed; initialization requires explicit fixture bootstrap, never automatic empty state |
| Valid | Missing | Fail closed; no automatic acceptance of an unanchored lone primary |
| Either corrupt, truncated, oversized, nonregular or noncanonical | Any | Fail closed; retain evidence, no older-file fallback or automatic deletion |
| Primary ahead, equal transaction/different digest, unrelated scope, gap or fork | Any | Fail closed; no winner selected by timestamps or largest integer |

Interrupted creation can leave only the watermark; it remains unexposed until
the caller explicitly accepts that exact candidate for this local experiment.
Temporary files are never candidates. Cleanup only deletes identified files
owned by the completed attempt; unknown/stale files remain for diagnosis.

The helper does not fsync the parent directory and offers no platform-specific
Windows power-failure persistence guarantee. Therefore this design promises
only conditional process-interruption recovery when completed file operations
remain visible. A machine crash, power loss, filesystem rollback, or failed
post-replace ACL operation can require fail-closed operator recovery. It does
not promise that an acknowledged transaction survives reboot. Adding such a
guarantee requires a separately reviewed platform durability mechanism.

## Trust and replay after restart

For the local experiment the caller independently supplies expected profile,
amendment, configuration binding and exact permitted snapshot digest. Tests
retain these in their controlling process; restoring a snapshot never produces
them. Cold restart lacking this input is unavailable. The caller must explicitly
select an interrupted candidate; neither a stored integer nor a valid signature
can silently advance the expected digest. This is an injected fixture trust
assumption, not a shipped bootstrap/provider interface.

Honest interruption tests establish file recovery and retained semantics only.
Restoring both files to older, internally valid bytes defeats local ordering
unless an independently retained expectation rejects them. A malicious host
that can also alter that expectation is outside this experiment. Production
requires an approved current governing configuration and rollback-resistant
floor/provenance source; none is selected, implemented or claimed here.

After restore, new packages still pass the full verifier with current independently
accepted context. R/E1 again is idempotent without writes; R/E2 adds its binding
atomically without reapplying enforcement; another R using E1/E2 rejects.
Terminal facts and floor cannot be reset by reopening. Recovery exposes retained
negative state, never permission to resume a service or restore authority.

## Windows ACL test authorization (separate, not granted)

At action time propose one fresh resolved directory of the form
`@LOCAL_USER_ROOT@\AppData\Local\Temp\nbsr-inclusion-restart-<UUID>`.
Disclose its exact generated path before requesting authorization. No ACL call
may target its parent Temp directory, checkout, user profile or production path.
Tests use public existing fixture bytes only. No keys or credentials are created.

Unchanged helper behavior: run `whoami` to resolve the current principal;
`icacls /inheritance:r /grant:r` gives full control to that principal, SYSTEM
(`S-1-5-18`) and Administrators (`S-1-5-32-544`). Directory grants include
`(OI)(CI)` inheritance; file grants are `(F)`. Remove explicit grants for
Everyone, Authenticated Users and Users. The helper hardens the test root,
each write temporary and each replaced destination. The lock inherits the
protected root's ACL. It does not set a new owner or modify global policy.

The helper does not remove every possible unrelated explicit ACE; inspect the
fresh root and resulting ACLs, and abort on unexpected grants rather than
silently treating the helper as an exact allowlist validator. Do not weaken
production ACL checks. Cleanup closes owned handles and removes only this exact
verified test root and its owned artifacts using literal paths; verify absence.
On cleanup failure retain and report the path, without broad ACL reset/deletion.
Production installation would instead need approved service identity, storage
location, ownership, writer allowlist and operator recovery policy; temporary
current-user test grants do not approve any of those choices.

## Proposed deterministic validation matrix

| Area | Required evidence |
|---|---|
| Codec | Exact round trip; original R bytes unchanged; missing/extra/duplicate fields; booleans; hash/profile/context mismatch; noncanonical bytes; existing byte and aggregate count limits and limit+1 |
| State | F rollback; scope/log/target mismatch; lower/forked lineage; terminal resurrection; removed marker/event; conflicting event binding; saturation preserves prior files |
| Replay | R/E1 restart retry; R/E2 retained across restart; successor/E2 rejected; unchanged idempotence writes zero bytes |
| Fault stages | Before temp creation, partial write, flush/fsync failure, before/after each replace, final ACL failure, before return; uncertain commits never report verifier rejection/success |
| Recovery | Every table row; no automatic empty bootstrap; no selection of temp files; no repair without exact caller expectation; repair failure stays unavailable |
| Ownership | Two cooperating repository instances; stale lock; wrong expected predecessor; lock release after normal failure; no cleanup of another attempt's files |
| Trust limits | Joint-file rollback rejected by independently retained expectation; explicitly demonstrate that local checksums alone cannot reject the same rollback; no runtime enablement |
| Filesystem | Authorized fresh-root Windows private writes and observed ACLs; fresh-instance reopen; deterministic injected failures without sleeps; no claim of power-loss durability |

Pure codec/state checks can precede filesystem authorization. File fault tests
must execute the real private writer once authorized; injected faults must not
bypass ACLs and then be reported as private-write evidence. Keep production
power-loss testing and real authority provisioning as separate unfulfilled gates.
Use existing resource supervisor, provisioned runtimes and focused neighbors;
preserve failed attempts and exact source/command hashes. No tests ran in this
design-only iteration.
