# Core v0.2 Independent Node.js Verifier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a dependency-free Node.js 24 verifier that independently reproduces the exact results of the checked-in Core v0.2 deterministic vector package.

**Architecture:** Keep the verifier under `tools/core-v02-node-verifier` and isolate it from Python and `nbsr/` runtime code. A strict manifest/package layer feeds a bounded RFC 8949 decoder, built-in Node Ed25519 verification, and a closed literal Core v0.2 semantic evaluator. The CLI is read-only and succeeds only when all 14 valid and 18 invalid artifacts match their declared outcomes.

**Tech Stack:** Node.js 24, ECMAScript modules, built-in `node:crypto`, `node:fs`, `node:path`, `node:test`, and `node:assert`; no npm dependencies.

## Global Constraints

- Work only on `codex/nbsr-v3-wp0-wp1`; do not modify or merge `main`.
- Do not push without an explicit user request.
- Use Node.js 24 and built-in modules only; no npm dependency, package lock, lifecycle script, network download, or native addon.
- Read `vectors/core-v0.2`; never rewrite, repair, or regenerate it from Node.
- Do not import or execute Python, `scripts/core_v02_vectors`, or `nbsr/`.
- Do not modify frozen Core v0.1 D1-D6, registries, schemas, message/error codes, states, transitions, critical extensions, or COSE wrappers.
- Do not add QUIC, TLS, DNS, sockets, origins, cloud behavior, WP3 runtime, multi-channel, migration, resumption, or handover.
- Preserve Core v0.2 version `2`, ALPN `nbsr-quic-1`, and D8 generic-close behavior.
- Use RFC 8949 deterministic bytewise map-key ordering, not legacy length-first ordering.
- Enforce exact CBOR limits: 65,536 total bytes, depth 16, 256 array items, 128 map pairs, 4,096 UTF-8 text bytes, and 32,768 byte-string bytes.
- Use fixed validation time `1893456000`; never use the wall clock.
- Never read or print the two checked-in private test seeds.
- Report vector IDs and bounded error summaries only; never print raw artifacts, signatures, COSE objects, public/private key material, or Origin Endpoint data.
- Treat cross-language vector agreement as conformance evidence only, not production readiness.
- Preserve unrelated untracked paths `.codex-test-temp-w4/`, `.superpowers/`, and `docs/leakguard_phase19_qa_pack/`.

- [ ] **Step 3: Implement the scanner and decoder**

Use an offset-based scanner. Parse arguments with preferred-width checks:

```javascript
const WIDTH_MINIMUM = new Map([
  [24, 24n],
  [25, 0x100n],
  [26, 0x10000n],
  [27, 0x100000000n],
]);
```

Represent maps as `Map`, byte strings as `Buffer`, integers above
`Number.MAX_SAFE_INTEGER` as `bigint`, and tag 18 as `new CborTag(18, value)`.
For every map, retain the complete encoded key slice and require
`Buffer.compare(previousKey, encodedKey) < 0`.

Reject tag 18 unless `allowTag18 === true`, and reject every other tag. After
one item, require `offset === data.length`.

- [ ] **Step 4: Implement the bounded deterministic encoder**

Encode integers with the shortest head. Pre-encode each map key, sort with
`Buffer.compare`, reject equal encoded keys, and decrement the remaining total
budget before recursively encoding the next item. Permit `CborTag(18, value)`
only when `allowTag18` is true.

Booleans must be checked before numbers because JavaScript does not use Python's
`bool` subtype relationship, but semantic validators must still reject boolean
where an integer is required.
