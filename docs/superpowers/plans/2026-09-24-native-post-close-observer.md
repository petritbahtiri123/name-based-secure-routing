# Native post-close observer qualification

The new finite mode now requests existing ownership diagnostics before work and
eleven-counter reports after close. Functional cleanup does not establish that
timing is unaffected. Before using this mode for a native ceiling reference,
measure five matched NBSR off/on pairs at exact source ac40740c, unchanged release
binaries, 16 KiB, eight streams, depth one, three-second warmup and twenty-second
measurement. Both roles share guest CPU 0. This is Docker/WSL evidence only.

Counterbalance off/on on odd repeats and on/off on even repeats. Reuse certificate
bytes within each pair, fresh namespaces and output roots per cell. Retain every
valid result, all failures and exact-PID absence checks. Do not run other benchmark
or build loads concurrently. Keep the five-GiB disk reserve and fixed deadlines.

Report paired goodput and p99 percentage changes and each mode's sample CV.
Qualification requires five valid matched pairs, zero workload errors, clean
owned process exit, all requested reports valid, absolute median paired goodput
and p99 changes at most five percent, and each mode's throughput CV at most five
percent. Variation above that threshold is INCONCLUSIVE_HOST_VARIANCE; a measured
median effect above threshold is REJECTED_OBSERVER_GATE. Neither result permits
causal production optimization or a strict-stable capacity claim. Direct's flag
does not enable these NBSR counters and is covered by functional equivalence tests.

Seal the raw cohort, independently revalidate pair packages and executed mode,
publish the calculated verdict and preserve the failed gate if any. No production,
wire, security, timeout or ACK changes are part of this measurement.
