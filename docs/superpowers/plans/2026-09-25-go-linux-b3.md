# Bounded Go-to-Rust Linux B3 coverage

Continue the accepted V2 memory/lifecycle and external validation program.
Current gap: run_b3_v2 exposes only Rust peers; LinuxCapture already measures
owned subprocesses independently of implementation, but final Go source exit
and its eight-field destination ownership scope require explicit treatment.

Scope: reuse run_b3_v2 with an explicit --path go-rust, default rust-rust unchanged.
Allow only sequential same-process cycles, channels and streams within existing
32-service/64-stream-per-service bounds. No Go bundle/process fanout, materialized
payload, allocator XML or admission-rate claim. Require the new destination
completion barrier for Go, and a destination report gate on Linux so its final
cooldown is live. Join the naturally exiting Go source before final cooldown;
represent unavailable final source metrics as null with verified process epoch
and exit, never zero. All existing cleanup/control/transport deadlines stay fixed.

Build and evidence gates bind actual Go/Rust release bytes, exact clean source,
Linux topology/affinity, declared workload, runtime samples and retained source.
Expose the narrower Go destination-eight/source-process-exit ownership contract;
never manufacture eleven source counters or call this full B3 closure. Preserve
existing Rust validation unchanged. Add an explicit Go analysis path rather than
silently feeding Go records into Rust-only ownership analysis.

Validate RED-first CLI/config/provenance/final-exit tests, affected Python tests,
Linux release functional smoke, then three valid memory/cycle repeats (five if
CV>5%). Preserve every failed run. Native two-host Go control, full resource
ownership instrumentation and observer-neutrality remain separate gaps.

monotonic component; leave Windows QPC unchanged. Cross-build RED proves missing
Now/Since. Require native Linux tests before accepting Linux measurements.

are retained separately; neither is a benchmark result.
