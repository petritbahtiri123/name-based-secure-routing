# NBSR V3.6 anti-drift checklist

**Status:** Required review checklist for forward-looking design and
implementation

Every protocol design, plan, change, review, or conformance claim must answer
yes to each applicable item:

- [ ] **Synthetic IP always:** every successful resolution through an upgraded
  NBSR network returns a scoped Synthetic IP.
- [ ] **Origin hidden:** no successful client response, route state, ordinary
  error, log, telemetry field, or fallback exposes an Origin Endpoint.
- [ ] **No direct fallback:** resolution or routing failure cannot redirect the
  client to an origin IP.
- [ ] **Service identity independent of IP:** mutable Origin Endpoints do not
  define or replace Service Identity.
- [ ] **Session reuse does not imply authorization reuse:** Transport Session
  authentication never authorizes another service.
- [ ] **Each Service Channel independently authorized:** name/service binding,
  revocation, quotas, audit attribution, and security context remain separate.
- [ ] **Legacy DNS is compatibility reachability only:** DNS TTL and DNS
  control do not become a Route Grant or authorization lease.
- [ ] **NBSR-native origin publication has precedence:** only valid, current,
  authorized, and unrevoked native data outranks delegated or legacy sources.
- [ ] **Stale or rollback origin updates rejected:** lower generation/sequence,
  resurrection, replay, and same-sequence different-content updates fail
  closed.
- [ ] **Frozen Core v0.1 registries protected:** D1-D6, 17 message codes,
  19 error codes, state registries, transitions, fields, deterministic CBOR,
  COSE wrappers, and `kid` bindings are not modified without approval.
- [ ] **Application authentication remains outside NBSR:** user login, OAuth,
  cookies, transactions, payload meaning, and database consistency remain
  application responsibilities.
- [ ] **No runtime implementation before required gates pass:** a plan or
  architecture statement is not authority to code a pending wire, issuer,
  cryptographic, mobility, handover, or drain decision.
- [ ] **New endpoints validated before use:** origin replacement is
  add/validate/activate/drain, never blind delete-and-replace.
- [ ] **Continuity preserves bindings:** migration, resumption, failover, and
  handover remain expiry-, revocation-, replay-, gateway-, client/device-,
  service-, and policy-bound.
- [ ] **Failure is contained:** one failed or revoked Service Channel does not
  unnecessarily terminate or authorize another.
- [ ] **Claims match evidence:** prototype, Core v0.1, extension, Core v0.2,
  and production claims remain explicitly separated.
